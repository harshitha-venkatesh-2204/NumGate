# NumGate

NumGate measures how many numbers in an LLM-written executive insight note are wrong, and which generation strategy reduces the error rate. It builds weekly sales report tables from public retail data, asks models to write 6 to 8 bullet insight notes under four strategies, and scores every note with an automatic two-level **number gate**:

- **Level 1, number support:** is each cited number a table cell or a fixed derived quantity (sum, share, percent change, and so on)? Output: the number-level unsupported rate.
- **Level 2, claim binding:** is each (entity, metric, period, value) claim attached to the right cell? Outputs: the **binding error rate** (a real number attached to the wrong entity, metric or period, research question 2) and the broader **claim error rate** (any wrong claim, including wrong values).

Strategies compared: **S1** Direct (table in the prompt), **S2** Compute-then-write (model writes pandas code, the code runs, the note is written from its facts), **S3** Write-then-verify (S1 draft, gate, up to two correction rounds), **S4** Facts-template (a deterministic facts packet narrated with numbers copied verbatim, an upper bound).

The gate rules are written out with worked examples in [docs/method.md](docs/method.md).

**Live dashboard:** [harshitha-venkatesh-2204.github.io/NumGate](https://harshitha-venkatesh-2204.github.io/NumGate/). **Paper:** [paper/numgate.pdf](paper/numgate.pdf) (also downloadable from the dashboard). The dashboard is rebuilt by `python src/analyze.py` and published by the workflow in `.github/workflows/pages.yml` on every push to `main`.

## Quick start

macOS or Linux:

```bash
./setup.sh
```

```bash
./run_all.sh
```

Windows:

```bat
setup.bat
run_all.bat
```

`run_all` downloads UCI Online Retail II (about 45 MB) on first use, builds the tables, runs the smoke experiment with the **mock** model (no API key, no cost), analyzes it, and opens the interactive dashboard `results/dashboard.html`.

**The dashboard** covers every run in `runs/` (switch between them at the top). Filter by strategy, model, table size and entity type; every tile, chart and table recomputes its rates and bootstrap intervals for the filtered notes. The note inspector shows each note with the gate's verdict on every number (hover a number to see its evidence and light up the table cell it matched) and every extracted claim.

Run the tests:

```bash
.venv/bin/python -m pytest -q
```

## Reproducing every number in `results/`

Everything is seeded (`seed: 42` in `config.yaml`) and every model response is cached under `cache/`, so a rerun reproduces the same notes at no cost.

1. **Tables.** `python src/build_tables.py` writes `data/tables/*.csv` and `data/tables/index.csv` (60 tables: 20 small, 20 medium, 20 large). It also checks that every derived column recomputes from the raw columns and exits with an error if one does not.
2. **Check the cost.** `python src/estimate_cost.py` prints the expected cost of the full run from the real prompt sizes.
3. **Notes and gate.** Set the API keys you need (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`), then:
   - smoke test with the mock model: `python src/run_experiment.py --smoke` (writes `runs/smoke/`)
   - one real model on the smoke tables: `python src/run_experiment.py --models claude-opus-5 --tables-per-size 2 --run-id smoke_opus`
   - full run: `MAX_BUDGET_USD=70 python src/run_experiment.py` (writes `runs/full/`)

   Notes are generated by `workers` parallel calls (4 in `config.yaml`, or `--workers N`), and each finished note prints a progress line with its cost.

   Each run writes `notes/<note_id>.json` (note plus full trace), `numbers.csv`, `claims.csv`, `notes.csv`, `config_used.yaml` and `run_settings.json`. Runs are resumable: saved notes are never regenerated, and Ctrl-C stops a run cleanly. The budget cap applies to each invocation (up to `workers` calls already in flight can finish after it is reached); if a run stops at the cap, rerun it with a higher `MAX_BUDGET_USD` to continue. `--gate-only` re-scores saved notes with the run's own settings; it replays cached extractor replies and calls the extractor only for notes whose reply is not cached.
4. **Analysis.** `python src/analyze.py --run-id full` (defaults to `full` if it exists, else `smoke`) writes:
   - `results/summary.csv`: unsupported rate and claim error rate by strategy, model, size, strategy x size and strategy x model, each with a 95 percent bootstrap CI (1,000 resamples over notes)
   - `results/figures/`: error by strategy, error by table size per strategy, error versus cost per note, S3 error per revision round
   - `results/report.html`: one self-contained page with the figures, tables, methods (filled from `config.yaml`), all prompts, and example notes with flagged numbers highlighted
   - `results/dashboard.html`: the interactive dashboard over every run (self-contained; open it in any browser)
   - `results/paper_numbers.md`: the headline numbers as sentences for the preprint, including paired strategy differences
5. **Gate validation.** `python src/make_audit_sample.py --run-id full` writes `results/audit_sample.csv` (200 numbers and 200 claims, stratified by strategy and label). Fill `human_label`, then `python src/score_audit.py` reports gate precision and recall per label.

## Adding a model

Add an entry under `models:` in `config.yaml` with `provider` (`anthropic`, `openai`, `openrouter` or `mock`), `model_id`, `price_in` and `price_out` in USD per million tokens, and `supports_temperature` (false for models that reject the parameter). Add its name to `experiment_models`. Any model on OpenRouter works with `provider: openrouter`. For a new provider, add a `call_<provider>` function in `src/models.py` that returns `(text, input_tokens, output_tokens, stop_reason)` and register it in the dispatch dictionary in `complete()`.

## Adding a strategy

Write a function in `src/strategies.py` with the signature `(table, meta, model, repeat) -> (note_text, trace)`. Start the trace with `new_trace()`, make every model call through `call()` so prompts, responses, tokens and cost are recorded, finish with `finish(trace)`, and pass the text through `clean_note()`. Keep its prompts in `prompts/`. Register it in `STRATEGIES` and add its key to `strategies:` in `config.yaml`. To keep the smoke run offline, teach `mock_model.respond()` to recognise its system prompt.

## Smoke-run results (mock model)

`python src/run_experiment.py --smoke`: 6 tables (2 per size), 4 strategies, 2 repeats, 48 notes. These numbers come from the mock model's planted error rates. They show the pipeline works, not anything about real LLMs.

| strategy | notes | numbers checked | unsupported rate (95% CI) | claims | claim error rate (95% CI) |
|---|---|---|---|---|---|
| S1 Direct | 12 | 180 | 10.0% (6.2 to 13.2) | 180 | 13.9% (9.7 to 17.4) |
| S2 Compute-then-write | 12 | 96 | 5.2% (1.0 to 10.4) | 96 | 7.3% (3.1 to 13.5) |
| S3 Write-then-verify | 12 | 180 | 1.7% (0.0 to 3.4) | 180 | 5.6% (2.7 to 8.7) |
| S4 Facts-template | 12 | 282 | 0.4% (0.0 to 1.1) | 282 | 0.4% (0.0 to 1.1) |

On the mock S1 notes the gate flagged 24 of 24 lines that contained a planted error, with no false flags on the 66 clean lines. This is a sanity check only: mock text is formulaic.

## First real-model results (Claude Opus 5, smoke set)

`runs/smoke_opus`: 6 tables (2 per size), 4 strategies, 2 repeats, 48 notes, $2.59 in API calls, claims extracted with Claude Haiku 4.5. A smoke set is too small for conclusions (the intervals are wide); it shows the harness works on a real model.

| strategy | numbers checked | unsupported | wrong entity or metric | any claim error | cost per note |
|---|---|---|---|---|---|
| S1 Direct | 514 | 0.6% | 0.0% | 0.6% | $0.049 |
| S2 Compute-then-write | 301 | 0.0% | 0.0% | 0.0% | $0.095 |
| S3 Write-then-verify | 514 | 0.0% | 0.0% | 0.0% | $0.053 |
| S4 Facts-template | 296 | 0.0% | 0.0% | 0.0% | $0.015 |

Every flag was checked by hand: the 3 unsupported numbers (and the matching 3 wrong group claims) are real Opus errors, all in one sentence that misreports a product-family total. The first version of the gate reported a 9.3 percent claim error rate on these same notes; at least 97 percent of its 110 claim flags were the gate misreading correct sentences (group totals, the extractor mislabelling periods, directions applied to levels, ambiguous short names). The fixes are described in docs/method.md, the regression cases are in tests/test_number_gate.py, and `paper/rescore_v1.py` reproduces the comparison.

- Held-out results (fresh notes the gate was never revised on): gate v2 on set 1 raised false alarms on 6.2% of correct numbers and 4.0% of correct claims; gate v3 on set 2 (`paper/heldout2/`, frozen by checksum, ground truth audited 140/140) raised 1.6% and 2.2%, caught 89% of wrong values at Level 1 and 95% of wrong claims at Level 2. At the Opus pilot's true error rate (0.18%) that still means only about 9% of Level 1 flags would be real errors, so flags should be confirmed by a person.
- Gate versions: v1 (built on the mock model; kept in `paper/v1/`), v2 (revised on the Opus pilot's flags; kept in `paper/v2/`, measured by held-out set 1), v3 (the current `src/number_gate.py`, revised on held-out set 1 and the pilot adjudication, frozen and measured by held-out set 2 in `paper/heldout2/`).
- Gate stress tests (`paper/stress/`): on 379 hand-labelled numbers and 203 hand-labelled claims written in varied LLM styles, Level 1 raised 2 false alarms on 291 correct numbers and caught 61 of 88 wrong numbers (most of the 27 misses are real cells attached to the wrong row or period, which is Level 2's job); Level 2 raised no false alarms and detected all 49 wrong claims. The fixes were tuned on these items, so treat them as a regression suite, not an unbiased accuracy estimate; the human audit is the real test.

## Assumptions

Data and tables
1. The UCI file has two yearly sheets that overlap from 1 to 9 December 2010. Invoices present in both are kept once, from the later sheet.
2. Cleaning also drops rows whose StockCode does not start with five digits (POST, DOT, M, BANK CHARGES, AMAZONFEE and similar non-product lines) and rows with country "Unspecified". Descriptions are trimmed and uppercased; the product entity is the Description.
3. A week is eligible when it has at least 4 trading days and so does the week before. LW is the preceding ISO week. LY is the same ISO week number in the previous ISO year; it is blank when that week is outside the data (weeks before 2010-W49). An entity with no sales in an LY or LW week that is in the data gets 0, and its WoW or YoY is blank.
4. Each table lists the top N entities by this week's revenue. Share_Pct and Rank are computed within the rows shown, so every derived column recomputes from the CSV alone.
5. Only about 13 countries trade in a typical week (maximum 20), so countries fill small tables only. The plan is 10 small country tables, 10 small product tables, 20 medium product tables and 20 large product tables.
6. Revenue is rounded to 2 decimals before derived columns are computed; percentages are rounded to 1 decimal. Revenue is GBP and the prompts say so.
7. The optional M5 source is not implemented. The builder prints a message and skips it with or without Kaggle credentials.

Models and calls
8. Default models: `claude-opus-5` (Anthropic), `gpt-4.1` (OpenAI) and `meta-llama/llama-3.3-70b-instruct` (open weights, via OpenRouter). Claim extractor: `claude-haiku-4-5`. Anthropic prices come from Anthropic's current price list; the OpenAI and OpenRouter model names and prices were not checked online and should be confirmed before a paid run.
9. The Anthropic provider uses the official `anthropic` SDK (1.x). That SDK has no typed `temperature` argument, so temperature is sent in `extra_body` for models that accept it. OpenAI and OpenRouter use `requests` against their chat completions endpoints. Dependencies beyond the spec list: `openpyxl` (reads the UCI Excel file) and `anthropic`.
10. Temperature is 0 where the model accepts it. Claude Opus 5 rejects the temperature parameter and thinks adaptively by default, so it runs with default sampling; `max_tokens` is 16,000 to leave room for thinking.
11. No refusal fallback is enabled for Opus. A fallback would switch to a different model mid-experiment and confound the model factor; `stop_reason` is recorded in each trace instead.
12. The cache key is (model, system, user, temperature) plus the repeat index. Without the repeat index, repeat 2 would always replay repeat 1 from the cache.
13. The budget counts only fresh calls. `cost_usd` in `notes.csv` is the nominal cost of the note and includes calls replayed from the cache. A cached reply that was cut off at the token limit is not reused when a later call asks for a higher limit.
14. Token counts for the mock model are approximated as characters divided by 4.

Strategies
15. S2 runs model-written code in a subprocess with the project's Python, a temporary working directory and a 30 second timeout. This is not a security sandbox. A note whose script fails twice is recorded as failed, excluded from error rates, and counted in the S2 failure rate.
16. S3's draft is the S1 note for the same table, model and repeat (a shared cache entry). Only Level 1 Unsupported numbers are flagged back to the model, with their line numbers.
17. S4's facts packet holds: totals (TW, LW, WoW, and YoY when available), the top 3 entities (rank, revenue, share, WoW), the largest WoW increase and decrease, the largest YoY increase and decrease when available, and the entity with the most orders.
18. `clean_note()` keeps only bullet lines if a model adds a preamble. The format check (`format_ok` in `notes.csv`) requires 6 to 8 bullets, each with a number, and no em dash.

Gate and statistics
19. Unsigned numbers are matched on absolute values; direction words sign a number; ranks are checked against Rank rather than skipped. Pairwise derived values are only computed for entities named in the same line (see docs/method.md, section 2.4).
20. Level 2 labels a claim Unverifiable when the entity is not found and also when the table cannot answer the metric and period (for example units YoY).
21. The claim error rate excludes Unverifiable claims from its denominator; they are reported separately.
22. CIs are percentile bootstrap intervals over notes with a pooled-ratio estimator. Strategy differences in `paper_numbers.md` use a paired bootstrap on conditions matched by table, model and repeat.
23. The mock model's error rates are fixed in `src/mock_model.py` (18 percent of numbers per slot for S1, 7 percent for S2, 3 percent for S4; S3 fixes a flagged line with probability 0.8 per round).
24. Python 3.12 was used to build and test this harness; the code targets 3.11 and 3.12.
25. Research question 2 ("claims that bind a number to the wrong entity, metric or period") is answered by the binding error rate, (Wrong_entity + Wrong_metric) / verifiable claims. A period mix-up (the YoY figure cited as WoW) is a Wrong_metric, because each period is its own column. The claim error rate adds Wrong_value.
26. A note whose claims the extractor cannot return as valid JSON (after one retry) is left out of the claim rates and marked `extract_failed`; the rule-based extractor is used only for the mock model.
27. Level 1 searches the line's own entities first, then values derived from them and their groups and families, then table-level values (only on lines that name no entity or use an aggregate word), then any other cell. The spec's order "cell, then derived" is kept within each step; putting the line's own derived values before other rows' cells makes the evidence point at the right place.
28. S2 error messages have machine-specific paths replaced (temporary folder, Python install, tables folder) before they go into the retry prompt, so reruns hit the cache.
29. In `numbers.csv`, ranks have unit `count` and `is_rank` true; the `qualifier` column records hedges (approx, over, under).
30. S3 per-round rates: a note that stopped revising early carries its last rate forward to later rounds; a round with no checkable numbers counts as 0.
31. The cost estimate (`src/estimate_cost.py`) measures real prompt sizes at 3 characters per token and assumes 350 output tokens per note, 700 per S2 script, 0.2 extra S2 code calls and 1.5 S3 revisions per note, a 2,500-character S2 facts JSON, 1,500 thinking tokens per Opus call, and 900 input and 700 output extractor tokens per note. The Opus smoke run cost $0.054 per note on average.
32. Matching uses half-up rounding on magnitudes (6.5 rounds to 7), with signs compared separately.
33. Group figures are checked at Level 2 against the same group, family, top-k and table values as Level 1; group shares equal to the sum of the table's rounded Share_Pct cells are accepted (a policy choice; counting them strictly would add 6 unsupported numbers to the Opus pilot).

## Limitations

- **Single data domain.** One UK online retailer, GBP, weekly grain, and country and product entities only. Results may not transfer to other table shapes such as finance or operations metrics.
- **The gate can miss paraphrased numbers.** Numbers written as words ("doubled", "a third", "two-fold") are not extracted, so they are neither supported nor flagged.
- **Finite operation library.** A correct derived number outside the library (for example a multi-week average) is labelled Unsupported. In large tables a wrong number can coincide with an unrelated cell and pass Level 1; Level 2 catches this only when the claim names an entity.
- **Extractor model errors.** Level 2 depends on the claim extractor. A wrong entity or period from the extractor produces a false Wrong_* label. The rule-based extractor is tuned to the mock model's phrasing and should not be used to score real models.
- **S3 is scored by the gate it optimizes against.** Its Level 1 rate is biased low by construction; compare strategies on the Level 2 claim error rate and the human audit.
- **Strict rounding.** Truncated values cited without k or M count as unsupported.
- **The mock check is not validation.** Gate precision and recall on real notes must come from the human audit (`make_audit_sample.py`, `score_audit.py`).
- **Sampling.** Opus 5 cannot run at temperature 0, so its repeats vary more than the other models'.
